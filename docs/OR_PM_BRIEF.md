## 一句話講完

> **教電腦看 15 年資深排班師怎麼排班，然後讓它一鍵幫所有新人完成季度排班，而且比人排得更好。**

## 1. 我們要解什麼問題

**老闆原話**:
> 「我們這行最大的問題是**新的排班師找不到人**。現在的老師傅做得不錯，但都快退休了。」

**業界現況**:
- 一個 DC（配送中心）每天要排 20+ 個物流士 × 27 個門市的送貨順序
- 排班師要 **15 年經驗**才能上手 — 知道哪家店老闆要 6 點前送到、哪條路晚上會塞車、哪個物流士不愛跑山區...
- 新人 **3 年內**根本接不了
- **沒人接班 = 整個 DC 排班崩盤**

**現在公司怎麼做**:
- 老師傅靠經驗手動排，**成效不錯**（這是關鍵 — 不能丟掉）
- 但只有他一個人會，他請假就完蛋

**我們要做的事**:
- 把「老師傅的經驗」變成電腦看得懂的東西
- 主管按一個鈕，電腦就排完一整季

## 2. 為什麼我們的做法跟別人不一樣

**業界其它人怎麼做（劇透：做不好）**:

| 別人的做法 | 為什麼不行 |
|---|---|
| 用 Google Maps 算最短路徑 | 只考慮距離，不管時間窗 / 工時公平 / VIP 客戶 |
| 直接套 OR 算法（純數學最佳化） | 算出來的路徑老師傅看了搖頭 — 「現實沒這樣走的」 |
| 用 ChatGPT / AI 寫個答案 | 不穩定，每次答案不一樣，物流士無所適從 |

**我們的核心招數**:

```
       ┌─────────────────────────────────┐
       │ 步驟 1: 偷學                     │
       │                                  │
       │ 把老師傅過去 2 季排的所有路線    │
       │ 餵給電腦，讓電腦自己反推         │
       │ 「老師傅心裡到底在乎什麼？」     │
       │                                  │
       │ 答案不是文字，是 5 個數字：      │
       │   距離 40% / 準時 30% / 容量 15% │
       │   / VIP 8% / 公平 7%             │
       └─────────────────────────────────┘
                       ↓
       ┌─────────────────────────────────┐
       │ 步驟 2: 規模化                   │
       │                                  │
       │ 拿這 5 個數字，餵給數學最佳化    │
       │ 引擎 (OR)，自動算出新方案        │
       │                                  │
       │ → 老師傅的判斷力 × 電腦的速度    │
       └─────────────────────────────────┘
                       ↓
       ┌─────────────────────────────────┐
       │ 步驟 3: 講人話                   │
       │                                  │
       │ 給主管看「為什麼這樣排」，例如:  │
       │ ・冷凍貨先送（避免融化）         │
       │ ・新人路線比較短（還在學）       │
       │ ・S087 排第 7 站（時間窗 6-9pm） │
       └─────────────────────────────────┘
```

**一句話**: 不是電腦取代老師傅，是電腦學完老師傅之後**複製**他，讓所有 DC 都有一個「虛擬老師傅」。

## 3. PM 你只要記住這 5 件事

### ① 一鍵生成
主管端 UI 只有一顆大按鈕：「**一鍵生成本季排班**」。按下去 30 秒內出方案。

### ② 五層架構（不用記名字，記功能）

| 層 | 在做什麼 | 多久跑一次 |
|---|---|---|
| 學歷史 | 從歷史路線學「老師傅的判斷」 | 一個月一次 |
| 戰略 | 決定「**誰**固定跑**哪片門市**」 | 一季一次 |
| 戰術 | 決定「今天這 27 站**怎麼排順序**」 | 每天一次 |
| 自動駕駛 | 自動決定用哪個算法（主管不用選） | 每次按按鈕 |
| 解釋 | 告訴主管「**為什麼**這樣排 + 比歷史好多少」 | 每次出方案 |

### ③ 五個比較指標（給主管看）
每次出方案，跟歷史比這 5 個：
- 總里程少幾 %
- 準時率高幾 pp（百分點）
- 工時公平度（最累 vs 最閒差幾分鐘）
- VIP 客戶觸達率
- 信心分數（0–1，<0.6 紅標必須主管手動審）

### ④ 三種模式
- **預設**: 自動駕駛（一鍵出方案）
- **進階**: 主管自己挑算法（14 種戰術人格選一個）
- **比較**: 同時跑 4 種，並排看

### ⑤ 失敗有 fallback
電腦掛掉、學不到、信心太低 → 自動退到「沿用上一季歷史排班」，**永遠不會排不出來**。

## 5. 時程 & 成本

| 階段 | 工時 | 完成定義 |
|---|---|---|
| **P0 端到端可 demo** | **8 工作天** | 老闆可以按下按鈕看到結果 |
| P1 補完進階功能 | 11 天 | 14 種戰術人格全到位 |
| P2 真正智能化 | 5 天 | 急件即時插入 + RL 自學 |

**P0 拆解** (8 天)：
- 灌歷史資料 + 地址轉座標 = 1 天
- 戰術層 baseline + VRPTW = 2 天
- 戰略層 Hungarian = 1 天
- 學歷史 MVP = 2 天
- 自動駕駛 + 一鍵按鈕 = 1 天
- 解釋層 = 1 天

**多人協作可平行**: backend 4 天 + frontend 4 天 並行 = 4 天 elapsed。

**外部成本**:
- TomTom API (地圖 + 地址解析): 已有 key，免費額度夠
- OR 引擎: 開源 (Google OR-Tools)，0 元
- 雲端: 多一個 Python sidecar container，<$10/月

## 6. 怎麼算成功（PM 你要 track 的 KPI）

| 指標 | P0 目標 | 怎麼量 |
|---|---|---|
| 學歷史準確度 | Kendall-τ ≥ 0.6 | hold-out 預測準確率 |
| 一鍵生成時間 | < 30 秒 | 按鈕點下到結果出來 |
| 對比歷史 — 至少贏 1 個 | 距離 / 準時 / 公平 三選一 | A/B 對比 |
| 主管採用率 | 50%+ 方案被採用 | UI track |
| 物流士抱怨率 | 不增加 | 異常回報 dashboard |
| 信心分數平均 | ≥ 0.7 | 系統自動算 |

**警報線**: 連續 3 次方案信心 < 0.6 → 重新訓練學歷史層。

## 7. 預期 PM 會被問的 10 個問題

**Q1: 如果老師傅突然辭職，系統還能跑嗎？**
A: 能。學歷史只要有過去 2 季資料就夠了，老師傅在不在公司不影響。

**Q2: 物流士會不會抱怨「機器排得我不會跑」？**
A: 不會。我們戰略層季度綁定 driver-route，物流士跑的還是他熟悉的那片區。戰術層每日順序由系統算，但解釋層會講「為什麼這樣排」。

**Q3: 如果歷史資料品質很差怎麼辦？**
A: 系統會偵測到「信心分數低」自動退到 sweep heuristic 純數學排，並 alert 主管。

**Q4: A 點到 C 點以前沒跑過，電腦怎麼知道距離？**
A: TomTom Maps 算地理距離 — 不需要歷史曾經跑過。學歷史學的是「權重」（老師傅多在乎距離 vs 準時），不是具體路徑。

**Q5: 新門市開幕怎麼處理？**
A: 用門市主檔的「平均服務時間 + 預期貨量」當預設值，標 `is_new` 給解釋層提醒主管多看一眼。

**Q6: 新 DC 沒任何歷史怎麼辦？**
A: 三層 fallback — 借同區 DC 權重 → 全網平均權重 → 均勻權重 + 信心分數標紅。

**Q7: 急件臨時加單怎麼處理？**
A: P2 補完。P0 先做「沿用歷史插入位置」的規則。

**Q8: 老師傅看到電腦排的不滿意怎麼辦？**
A: P1 加「按讚 / 按倒讚」按鈕，下次學歷史會把倒讚的方案排除。

**Q9: 這算 AI 嗎？要不要找 AI team 一起？**
A: 算「應用機器學習 + 數學最佳化」。學歷史那部分是 ML（inverse optimization），其它是 OR。不用找 AI team — 算法都是 60 年代就有的成熟工具。

**Q10: 對比之前 mock 的 OR 模組，差別在哪？**
A: Mock 是「平均分配 + 固定 10 分鐘間距」— 完全沒最佳化。新版有真實算法 + 學歷史 + 自動駕駛 + 解釋 — 整個閉環是新的。
